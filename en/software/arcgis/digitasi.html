Spatial Data Recovery: Salvaging Cigombong Land Parcel Assets

Rivaldi Fiqriyansah — Land Surveyor

Context: The Loss of Vector Data

In land asset management, the absence of valid spatial data poses a significant risk. The case in Cigombong, covering a total area of approximately 10.7 hectares with around 60 parcels, is a prime example. The final vector data from previous measurements could not be found.

The only remaining data were raw measurement files in CSV format and a final output image in PDF format. Initial comparative analysis revealed discrepancies between the CSV data and the PDF geometry. Based on team decisions and senior directives, the PDF document was ultimately established as the source of truth for geometric reference.

Geoprocessing Workflow

  1. Georeferencing: Anchoring the PDF document into a spatial coordinate system using 4 precise control points to match the actual orientation and scale.
  2. Geodatabase Structuring: Creating a new, project-specific File Geodatabase (.gdb) via the Catalog pane, followed by the creation of a polygon Feature Class for the parcels.
  3. On-Screen Digitizing: Manually extracting vector data by tracing the land parcel boundaries on the georeferenced PDF, ensuring the topology of every polygon is completely closed without any gaps.

Data Enrichment & Final Output

The final step involved bringing the empty polygons to life by adding a new attribute structure (Add Field) to the Feature Class. The added information includes:

  • Landowner Name (as ownership identity).
  • Land Area (m²) (based on automated geometric calculations).
  • Hectare Area (Ha) (as a macro-level regional reference).

Following a cross-check phase with the original PDF document, all land assets are now securely stored within the Geodatabase.
